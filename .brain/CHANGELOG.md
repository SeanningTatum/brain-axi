# Brain Changelog

High-level project + brain changes. **Not a code changelog** (see `git log` for that). This tracks:

- Architectural shifts (e.g. "migrated to X")
- New features shipped (with link to `features/<slug>.md`)
- Brain restructures (folder splits, doc rewrites)
- Decisions reversed
- External constraint changes (legal, vendor, deadline) sourced from `transcripts/` or `emails/`

## Conventions

- Newest entry on top
- Date format: `YYYY-MM-DD`
- One entry per change. Use the type tags: `feature` `bugfix` `refactor` `decision` `brain` `chore`
- Link out: `See .brain/features/<slug>.md`, `See .brain/transcripts/<file>.md`, `See PR #<n>`

| 2026-07-31 | bugfix | **state-integrity phase 4 — the strict gate was unusable, and two more spoofs.** A third adversarial review found that `--strict`, being always-on at the ship path and scoped to the WHOLE brain, meant one legacy feature predating the invariant refused **every** future ship in both repos — the flagship gate was decorative exactly where it lives. `brainCheck` gained `opts.strictScope`: ambient `brain check --strict` still audits the whole brain (that is the report), while both ship paths scope the proof requirement to the feature being shipped (that is the gate). Two new verdict spoofs closed: a fence closed by MORE backticks than it opened (CommonMark closes on `>=`, the `\1` backreference required exact length) and a verdict inside an HTML comment (renders as nothing, parsed as real — the `brain:verification` receipt is itself a comment, so it is preserved by negative lookahead). Assertions 149 to 156, including a fence/comment matrix asserting the parser never scores a verdict a renderer would hide. |
| 2026-07-31 | feature | **state-integrity phase 3 — receipts, telemetry, and the clone case.** Verdicts are now bound to code: a `brain:verification` receipt names the commit a verdict was taken against, and `--strict` (plus both ship paths, always) requires that commit to exist **and** be an ancestor of HEAD — a PASS taken on a branch that never landed describes code that is not what shipped. Outside a git repo, presence is the ceiling and provenance is reported unverifiable rather than failing. `brain ship` became transactional across its two files: the feature-list bytes are snapshotted and restored if the checkpoint write throws (a *missing* `progress.md` still only warns — `appendProgressEntry` returns null by design so a brain without a cursor can still ship). New `brain metrics` over an append-only `runs/gates.jsonl` written by every `brain verify`: first-pass rate, per-check failure counts, p50/p95 duration, and it names any check that has never failed in 3+ runs. New `brain init --state-only` for repos cloned from a template — wipes inherited `features/`, `runs/`, `plans/`, `screenshots/`, `evals/`, keeps `rules/`, `recipes/`, `codebase/`, `high-level-architecture/`, `HARNESS.md`, `verify.json`. Assertions 124 to 149, with provenance fixtures built against a throwaway git repo (orphan commit, unknown sha, missing receipt). |
| 2026-07-31 | feature | **state-integrity phase 2 — closing what adversarial review found.** Two independent reviewers audited phase 1; between them they found one P0 and several P1s, three of which were regressions phase 1 introduced. `features set-status --status shipped` was a complete bypass of the new ship gate (hardening `ship` alone moved the hole rather than closing it) — it now runs the same projection preflight; transitions *out* of a state stay ungated so broken records remain repairable. `oneInProgressEnforced()` is now shared, because the setter and checker had drifted apart a second time in the opposite direction (absent policy: setter said not-enforced, checker said enforced). Verdict spoofs closed: 4-space indented code blocks, unclosed fences, and a trailing contradicting emoji each scored a clean PASS; the token must now lead its value and identical restated verdicts are accepted rather than called ambiguous. Drift check fixed for one false positive (prose with a pipe) and four false negatives (capitalized status, two status words in a row, first-match-only attribution, features absent from the index). `loadFeatureList` hard-fails on structure only — full-field failure had locked `features set-status` out of repairing the very records it exists to fix. New: **`brain check --strict`** requires a PASS verification for every shipped feature — opt-in ambiently for read-compat, always enforced at both ship paths. Assertions 78 → 124. |
| 2026-07-31 | decision | **`brain ship` is now preflight-then-commit.** It previously wrote `feature_list.json` and appended the progress checkpoint, THEN ran `brainCheck`, then exited 1 with the flip already on disk — specified behavior (`docs/REVIEW-ARCHITECTURE.md`), reasoned as reporting the failure honestly. Reversed: reporting a failure honestly does not stop later reads from seeing a feature marked `shipped` on a brain that never passed its checks. `brainCheck` gained `opts.list` so a projection is validated before any write; on failure nothing is written and the previous status stands.
