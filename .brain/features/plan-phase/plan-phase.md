# Feature: Plan phase — grill before the artifact, register for the record

_Last updated: 2026-08-10_

## Purpose
Two standing playbooks plus the enforcement that makes them stick. `grill` interviews the human
before a plan artifact exists, and checks the brain for an already-settled answer before asking
anything. `write` gives the written record — checkpoints, run notes, feature docs, verification docs,
commit bodies — a reference register instead of a release-note one.

The gap both close: nothing in the plan phase asked a question until the artifact was already
designed, and no playbook said how to write what `execute` and `done` instruct you to write.

## When It's Used
- `grill` — after `playbook start`, before `playbook plan`, whenever the plan will carry a decision card
- `write` — every time any brain artifact is written; `execute` and `done` point at it at each write step
- Plan tiering — at the top of every `playbook plan` run
- The `progress add` length gate — on every checkpoint write

## How It Works
- **`playbook grill`** runs rounds against a design tree. The *frontier* is every decision whose
  prerequisites are settled; the whole frontier is asked in one numbered round, each question carrying
  a recommended answer, then the agent waits. Answers reshape the tree and the frontier is recomputed.
  Facts are the agent's job (dispatch a sub-agent, run `brain search`); decisions are the human's.
- **The memory check** runs before any question is asked. It reads `tag: decision` targets out of every
  `reviews.jsonl` in the brain plus the docs sections. On a hit the question is cited, not asked —
  one line offering to reopen. This is the step a stateless grilling skill cannot have.
- **Grill output** lands in the plan artifact: settled answers become pre-answered decision cards,
  memory hits become Context citations, unsettled ones become open questions. No new file format;
  answers reach `reviews.jsonl` through the normal review queue.
- **`playbook write`** carries one rule — the record is reference, not release notes — plus a slot
  skeleton per artifact type and three prune tests.
- **Plan tiering** adds a `small` tier beside the full 17 sections. The agent picks and declares it in
  the header strip, so a reviewer can push back in one annotation.
- **The length gate** makes `progress add` refuse a summary over 200 characters, exit 2, with the slot
  skeleton in the `help:` lines. `progress.md` already documented a one-line summary; nothing enforced it.

### Persistence details
- No new state files. Playbook text is a pure data module (`lib/review/playbooks.js`); grill output
  persists through the existing plan artifact and `reviews.jsonl`.
- The length gate rejects before any write — a refused checkpoint leaves `progress.md` byte-identical.

### Testability
Playbook content is checked structurally by `scripts/check-playbook-refs.mjs` (section refs, named ids)
and by `brain skill --check` (the generated skill must not drift). The length gate is checked by
`scripts/check-state-invariants.mjs` at both sides of the boundary plus a no-write assertion on refusal.

## Errors
No new tagged errors. One new refusal path.

| Error | Where raised | Surfaces as |
|-------|--------------|-------------|
| Summary over the cap | `brain progress add` | exit 2, `error:` line + `help:` carrying the slot skeleton; nothing written |
