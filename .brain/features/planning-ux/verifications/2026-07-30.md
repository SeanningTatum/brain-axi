## What was under test

The deliverable is authoring guidance, so the walk tests the guidance rather than hand-written HTML: the
demo artifact was assembled **verbatim from `brain playbook ux` sections 1-5** — the `.wf-*` CSS kit copied
out of the playbook's own text, plus its screen-inventory, state-matrix, user-journey and variant-card
examples. If the shipped playbook were wrong, this artifact would break.

## Console

- **jsErrors** — none in runs 1 and 2. Run 3 (offline) logged exactly one expected entry:
  `Failed to load resource: net::ERR_FAILED` for the blocked
  `https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs`. No `pageerror` in any run —
  the failed module import degrades without throwing.
- **networkErrors** — only the deliberately-aborted CDN request above, on the error path.

## Independence and agreement

Three runs, dispatched in parallel, each driving the app with its own script. Runs 1 and 2 walked the full
online path; run 3 walked the offline path and additionally re-ran itself to confirm reproducibility.
Every shared assertion returned byte-identical values across runs (fill color string, both bounding-box
dimensions, ack text, annotation counts).

Two runs initially reported incomplete evidence. Both causes were bugs in the **test scripts**, not the app:
each matched the artifact iframe by a text that also appears in the outer chrome and so drove the wrong
frame, and run 3's first draft shadowed the global `URL` constructor. Both were fixed and re-run in full.
Recording this because a green run whose failure was never explained is not evidence.

## Verdict rationale

PASS. The feature's central claim — that a plan's UI can be approved before it is built — depends on three
things being true at once: the wireframes render, a reviewer can annotate them, and neither depends on the
network. All three were demonstrated by independent runs that agree on every measured value, with the
`data-brain-action` carve-out verified as a negative test rather than assumed.
