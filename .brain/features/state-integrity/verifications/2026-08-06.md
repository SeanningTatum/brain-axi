## Limitations

- One artifact, unrelated to state-integrity's defects, surfaced repeatedly: `eval prompt pointers resolve` fails (`dangling: skill-coverage -> .claude/skills/brain/SKILL.md, skill-coverage -> bin/brain.js`) whenever `brain check` runs against **any** copy of `.brain` at a different filesystem path than the live one — including an **unmodified** copy (`brain-copy3`, tested standalone for exactly this reason). This is a path-resolution quirk in the eval-pointer check (pointers appear to resolve relative to cwd rather than the `--brain` argument), not a defect this feature's table claims to close, and it does not fire against the live `.brain/` (see the golden-path `check` transcript above, which shows 16/16 pass with this row passing).
- Defect #4 (commit-bound evidence via `brain receipt`) is verified by source inspection and command wiring, not by a live end-to-end stamp — see the table row above for why, and the recommended follow-up.
- Did not attempt a duplicate-slug or shipped-with-empty-evidence variant of the schema violation (E1) since the unknown-status variant already proves the same code path (`validateFeatureListShape`) rejects a malformed tracker; the feature doc's defect #1 doesn't distinguish between which specific field triggers the rejection.
