## Findings for main thread

FAIL cause (criterion 10, also E4):
- `skills/brain/SKILL.md:45` says `skill [--write|--check]` with "print/regenerate/validate this skill tree". `cmdSkill` (bin/brain.js, `cmdSkill`) only accepts `--check` and `--brain`. Change it to `skill [--check]` — print the router / validate the tree — and re-run `skill --check` and `evals run skill-coverage`.

Non-failure findings:
- F1. The 600 B context cap is satisfied only by this repo's current checkpoint (583 B, 17 B of headroom). `cmdContext` (bin/brain.js:3845) does not bound `last-checkpoint` or `next`; the checkpoint caps (200 chars summary) still allow 738 B. Today's next checkpoint with a longer `next` will break "at most 600 B". Truncate those two fields inside `cmdContext` or add a size check to `verify`/`skill --check`.
- F2. `brainPluginInstalled()` (bin/brain.js:5201) reads only `installed_plugins.json`; it ignores `enabledPlugins` and plugin scope. A disabled plugin still causes `setup --app claude` to delete the repo's SessionStart hook, leaving no context injection. Read by code inspection, not exercised.
- F3. skill-routing margin is one case: 31/34 = 0.912 against the 0.9 gate (30/34 would fail). `refuse-nobrain-done` shows `brain-done` firing in a repo with no `.brain/` ("is this done? can I open the PR"); the baseline arm passed that case, so the plugin made it worse. `product-dashboard-metric` and `edge-quick-bug` fire no brain skill. The run was recorded at commit d51f288; HEAD differs from it only in `.claude-plugin/plugin.json` (adds `experimental.evals`), so the skills tested are the skills at HEAD.
- F4. `claude plugin validate` warns: CLAUDE.md at the plugin root is not loaded as context. Harmless, but the plugin install carries the whole repo (plans, docs, evals-plugin, `lib/review/vendor` if committed) into the cache.
- F5. Plan phase 3 says delete `.claude/commands/*` and `.claude/skills/brain*`; `.claude/commands/` (4 files) remain and `.claude/skills/brain-axi/` remains. `brain-axi` is the vendored AXI standard (README line 98 explains it) so that one is likely intended; the commands are not explained. The plan's `commands/` plugin directory does not exist (skills double as slash commands per README line 88).
- F6. `CHANGELOG.md` has no entry for the plugin move (latest Unreleased block is dated 2026-09-30).
- F7. Aggregate file quirk: `evals-plugin/results/live-1791612975340/aggregate-result.json` reports `casesPassed: 42` but `overallPassRate: 0.9286` (39/42), the true pass count. The recorded run uses the per-case data, which recounts correctly.
- F8. `brain evals run skill-coverage` during this walk appended a run to `.brain/evals/skill-coverage/runs.jsonl` and created `.brain/evals/skill-coverage/runs/2026-10-10T06-24-00-389Z.json`. They are uncommitted (left for the main thread to keep or discard).
- F9. The home dashboard's `help:` list never mentions `brain playbook` or the skills (same at 45085ce, so not a regression); the "skill does not trigger" fallback relies on per-command `help:` lines plus the context `skills:` line.

## Verdict rationale

Criteria 1-9 and 11 pass on direct evidence: the 11-skill tree, caps and `## Next` chain are correct; all five `skill --check` breakages exit 1 with a specific problem; playbook output is TOON-only with the right exit codes; no normative content was lost across all 10 playbooks; the plugin validates, installs in an isolated config dir with 11 skills plus the hook, and the installed hook prints context; the setup matrix is idempotent and non-destructive; both evals gates hold and the routing numbers recount exactly from the raw aggregate. Criterion 10 fails: the router skill, which is the single most-read agent-facing surface and which the plan requires to stay in sync with the CLI, still documents `skill --write`, a flag this feature removed, and an agent following it gets exit 2. The fix is one line; a fresh verifier should re-walk everything in round 2.
