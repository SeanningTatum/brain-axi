## Findings for main thread

No finding blocks the PASS.

- F10. `brain skill --check` crashes with a Node stack trace (exit 1) instead of printing a `problems[]` line when a skill directory is deleted (`rm -rf skills/brain-done` gives `ENOENT ... lib/review/playbooks.js:25`) or a SKILL.md loses its frontmatter (`Error: skills/brain-write/SKILL.md: missing frontmatter`, `playbooks.js:27`). It happens because the loader throws at import time, before the validator runs. Exit code is right and the message names the file, but it breaks the AXI "error: plus help:" contract and also takes down every other command. Wrap the import in `cmdSkill`, or make `load` return a problem instead of throwing.
- F11. CHANGELOG says "the index lists refs" (under `playbook --ref`). `brain playbook` (the index table) does not list refs; `brain playbook <id>` does (`refs[8]` on `plan`). Reword to "`brain playbook <id>` lists its refs".
- F12. Malformed or non-object `settings.json` is silently treated as "nothing disabled", so a user who has the plugin disabled and a corrupt settings file loses the repo hook. Edge case; the safe direction is arguably the other way, but nothing crashes.
- F3, F4, F5, F7, F9 from round 1 are unchanged and remain non-blocking (routing margin of one case, plugin cache carries the whole repo, `.claude/commands/` and the vendored `brain-axi` skill retained, aggregate `casesPassed` quirk, home dashboard does not mention playbooks). F5 is now explained under "Deviations from the plan" in the feature memo.
- F8. `brain evals run skill-coverage` during this walk appended a run to `.brain/evals/skill-coverage/runs.jsonl` and created `.brain/evals/skill-coverage/runs/2026-10-10T06-29-43-977Z.json`; both are committed with this round.
