brain-axi, simplified: skills → AXI → SQLite library

2026-10-10 · feature: (new) axi-core (absorbs sqlite-engine, feat-012) · tier: full · reviewed · round 1

TL;DR

Three layers and nothing else. Skills hold the method and hand off in sequence. The AXI (bin/brain.js) is a thin shell over the library: parse args, call one function, print TOON with help: next steps. The library (lib/brain/) owns a SQLite database and exposes plain functions, one module per domain, with numbered migrations so it can be upgraded. The two browser UIs stay, as clients of the same library. 25 commands become 15; about 6–7k lines of file parsing, invariant scripting and dead commands go.

Product brief

Problem + evidence

  • Method and data are mixed together. Even after skills-plugin, the CLI still carries method commands (playbook, skill, brief, timeline, metrics, receipt, pr, setup). Your 2026-10-10 question: "what is playbook.js for when we can have it as part of the skill now?"
  • Storage logic is spread across 4 places. bin/brain.js (5,562 lines), lib/state.js (1,023), lib/review/brain-data.js (1,792) and lib/review/store.js (244) each parse .brain/ files. state.js's own header says two readers disagreed about the meaning of a Verdict line.
  • Invariants are checked after the fact. scripts/check-state-invariants.mjs is 3,325 lines asserting file-format rules that a schema enforces when the write happens.

User + job

The agent following a brain-* skill needs a small, stable set of commands whose TOON it can read and act on. Sean maintains it and needs to change behavior in one place: a library function, a migration or a skill, without hunting through layers.

Success metric

  • Commands: 25 → 15 top-level (counted from COMMANDS).
  • bin/brain.js ≤ 1,500 lines, with no fs calls on .brain/ content (grep-checked). Every state read or write goes through lib/brain/*.
  • Nothing outside lib/brain/ imports node:sqlite (grep-checked).
  • skill-routing eval re-run on the new surface: ≥ 0.9 non-held-out (baseline 0.912).

Non-goals

  • No migration for existing file brains in other repos (settled: new brains only). This repo gets a one-off live-parts import.
  • No codex/opencode support (settled: Claude only).
  • No new features inside the UIs. They are re-plumbed onto the library, not redesigned.

Function contract: plain functions taking a db handle first, returning plain objects, and throwing a typed BrainError {code, message, hint} that the CLI maps to exit codes and help:. No printing, no process.exit. Writes run inside transactions.

Built to be upgraded

  • Schema: numbered migration files in migrations/NNN-*.sql, tracked by SQLite's built-in schema version number. Opening the DB with a newer CLI copies it to brain.db.bak-vN, then migrates forward in one transaction. A DB newer than the CLI is refused with "upgrade brain-axi".
  • Behavior: one library function per operation, so a change lands in one place, with a test next to it.
  • Surface: the plugin version must equal the npm version (checked by the dev script). Skills only name commands that exist (also checked). The export format carries version:, so import can read old dumps.

The two UIs, on the new architecture

lib/review/server.js keeps HTTP and sessions. It stops reading .brain/ files: brain-data.js (1,792 lines), store.js, evals.js and playbooks.js are deleted, and the server calls lib/brain for plans, rounds, prompts, features, run steps and verifications. The static assets (chrome, sdk, lightbox, dashboard, vendored mermaid) are unchanged. The review loop's on-the-wire contract (window.brain.queuePrompt, the poll payload) stays the same, so plan artifacts and the brain-plan skill keep working.
